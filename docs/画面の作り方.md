# Level Sketch の画面を作る

初号機の共通条件はUNO R3（ATmega328P）、MSP2807、標準回路、手操作のMODE/SPEED/VIEWタクト3個。J3のセンターマイナス9 VまたはUSB-Bで給電し、作品を書き込むときはUSBを使う。猫の顔は [AmpCat](../firmware/LevelSketch/examples/AmpCat)、屋上の全画面プレビューは [RooftopPatrol](../firmware/LevelSketch/examples/RooftopPatrol)、針は [Needle](../firmware/LevelSketch/examples/Needle)、アタック履歴は [PickHistory](../firmware/LevelSketch/examples/PickHistory) をフォルダごとコピーして始める。各作例は独立したスケッチ。MultiViewに反映する場合は、変更した描画コードをそちらにも移す。猫の画像は使う画像の宣言とデータが作例ごとに異なるため、画像の生成元を編集して対象フォルダごとに再生成する。以下は複数画面を組み合わせるMultiViewの手順。

1. `firmware/LevelSketch` をArduinoのスケッチブックの `libraries` にコピーする。旧版から更新する際は、旧フォルダをバックアップしてからフォルダ全体を置き換える。古い `src/AmpCat.cpp` などを残したまま上書きしない。IDEのライブラリマネージャーで **Adafruit ILI9341 1.6.3** と依存ライブラリを導入する。ボードは「Arduino Uno」。
2. 「ファイル → スケッチ例 → LevelSketch → MultiView」を開き、新しい名前で保存する。`.ino` だけでなく、同じフォルダの `.cpp` と `.h` も一緒に保存・共有する。猫メーターは `AmpCat.cpp`、待機画面は `RooftopPatrol.cpp` のタブで編集できる。ライブラリ本体を編集する必要はない。下の例のように描画関数を追加し、`pages[]` に表示順で登録する。配線図は `hardware/LevelSketch.fzz`。
3. 描画範囲は240 × 320の縦画面の **y=118～319**。上部に共通の絶対・相対表示と操作メッセージが出る。ADCはA0を連続使用するのでスケッチからanalogReadを呼ばない。全画面画像をSRAMに展開せず、変わった領域だけ描く。draw内で待たずにループへ返す。
4. 改変したスケッチをUNOへ書き込み、同じフレーズを弱く、次に強く弾いて表示を比べる。VIEWを長押しして待機画面も試す。

## スケッチ冒頭の共通設定

`MultiView.ino` は共通設定と作品の選択をまとめる場所。`setup()` で `Config` に設定を移し、`LevelSketch::begin(config)` に渡す。

| 設定 | 初期値 | 意味 |
|---|---|---|
| `IDLE_TIMEOUT_MS` | `60UL * 1000UL` | 最後の音・ボタン操作から待機までの時間 |
| `IDLE_THRESHOLD_COUNTS` | `5.0f` | 音ありと判断するADC RMSのしきい値 |
| `SLOW_RESPONSE_MS` | `300` | SLOWの針用の平滑化時定数（ms） |
| `FAST_RESPONSE_MS` | `60` | FASTの針用の平滑化時定数（ms） |
| `START_IN_RELATIVE` | `true` | 起動時REL。`false`ならABS |
| `START_IN_FAST` | `false` | 起動時SLOW。`true`ならFAST |

`pages[]` は演奏画面の順番、`idleArtwork` は待機作品の選択。`idleArtwork = nullptr` なら待機作品を使わない。共通の応答設定は `Frame.needleDb` に反映される。猫メーターは従来どおり平滑化前の `Frame.rmsCounts` を使い、感度や上昇量、まばたきは `AmpCat.cpp` 側で決めている。ここも作者が自由に変更できる。

## 演奏画面を追加する

標準MultiViewの演奏画面は針と丸顔の黒猫の2枚。たとえば3枚目にピーク値のバーを追加する場合、`pages[]` を次の定義に置き換える。

```cpp
void paintPeak(const Frame& f, bool entered) {
  int width = constrain(int(f.peakCounts * 0.4f), 0, 220);
  display.fillRect(10, 205, 220, 12, INK);
  if (width > 0) display.fillRect(10, 205, width, 12, MINT);
}
const Painter pages[] = {paintNeedle, paintAmpCat, paintPeak};
```

登録数に固定上限は設けない。UNOでは配列の1項目は2バイトの静的RAMを使い、各画面の描画コードはフラッシュ、履歴などの変数はRAMを使う。追加のたびにArduino IDEのコンパイル結果で両方の使用量を確認し、スタック用の余裕も残す。表示中の関数だけを呼び、切替直後は下段を消去して `entered=true` を渡す。旧PickHistoryは任意の単独例として残しているが、標準の切替には登録していない。

## 全画面の待機作品を作る

`setIdlePainter()` に登録する関数は、上部の数値欄を含む **240 × 320の全画面** を使える。演奏用の `pages[]` に追加する必要はない。標準作例はスケッチ内の `RooftopPatrol.cpp`。以下は、コピーしたMultiViewの他のタブを残したまま `.ino` を置き換える最小例。

```cpp
#include <LevelSketch.h>
#include "SketchViews.h"
using namespace LevelSketch;
using namespace SketchViews;

constexpr uint32_t IDLE_TIMEOUT_MS = 60UL * 1000UL;

void paintMyIdle(const Frame& f, bool entered) {
  static uint8_t previous = 255;
  if (entered) {
    display.fillScreen(INK);
    display.setTextSize(2);
    display.setTextColor(PAPER, INK);
    display.setCursor(42, 100);
    display.print(F("PLAY TO WAKE"));
    previous = 255;
  }
  uint8_t phase = (f.timeMs / 700) % 2;
  if (phase != previous) {
    display.fillCircle(120, 170, 10, phase ? MINT : AMBER);
    previous = phase;
  }
}

const Painter pages[] = {paintNeedle, paintAmpCat};
void setup() {
  Config config; // 未指定項目は上記の初期値を使う
  config.idleTimeoutMs = IDLE_TIMEOUT_MS;
  LevelSketch::begin(config);
  LevelSketch::setIdlePainter(paintMyIdle);
}
void loop() { LevelSketch::update(pages); }
```

`entered=true` で背景と内部の描画状態を初期化し、その後は変化した部分だけ描く。`delay()` や毎回の全面描画を避け、測定やボタン処理へ速やかに戻す。新しい `.cpp` に描画関数を分ける場合は、既存の作品と同様に `SketchViews` 名前空間で定義し、`SketchViews.h` に宣言を追加する。

標準の猫は2ビット画像をフラッシュから読み、前後の差だけ描く。画像データはスケッチ内の `BlackCatArt.cpp/.h`、差分描画は `CatDrawing.cpp/.h`。画像の生成元を変更した場合は、プロジェクト直下で `node tools/generate_cat_art.mjs` を実行するとMultiViewの画像を再生成する。別の作品なら `node tools/generate_cat_art.mjs "スケッチフォルダのパス"` のように出力先を指定する。生成される画像は各スケッチのBlackCatArt.hで決まる。AmpCatには顔、RooftopPatrolには全身のポーズ、MultiViewには両方を書き出す。

共通処理が60秒の無音を判定し、待機作品を呼ぶ。音を検知すると計時をやり直す。音やボタンで元のメーターへ戻り、ボタンの通常操作も行う。ボタン操作後も設定した時間は待機に入らず、基準設定・校正・メッセージ表示中も呼ばない。`setIdlePainter(nullptr)` で無効にできる。

VIEWを約0.7秒長押しすると、無音の待ち時間を省いて待機作品へ入れる。選択中の演奏画面は変えず、長押しを離しても待機を続ける。長押し時点で音がある場合は、いったんしきい値未満になった後の新しい音で復帰する。すでに無音なら次の音で復帰する。ボタン操作でも復帰し、VIEWの短押しは離したときに次の演奏画面へ進む。校正・基準設定・メッセージ表示中は手動待機も無効。待機への切り替えと復帰を試すにはMultiViewを使う。

待機時間はスケッチ冒頭の `IDLE_TIMEOUT_MS` を変更する。単位はミリ秒で、未指定時は60秒。例えば `120UL * 1000UL` は2分。32ビットで扱うため65秒を超えても設定できる。UNOでの計算の桁あふれを防ぐため `UL` を付ける。音あり／無音のしきい値も同じ場所の `IDLE_THRESHOLD_COUNTS`（標準5カウントRMS）で設定でき、相対基準や測定ゲートとは独立している。起動後に時間だけ変更したい場合は従来の `setIdleTimeoutMs()` も使える。

待機中も測定とシリアル出力は続く。動きを派手にした場合もシリアルの `dropped` を見て、定常表示中に増え続けないことを確認する。

| 作者が受け取れる値 | 意味 |
|---|---|
| `rmsCounts / peakCounts` | 256サンプルからDCを除いた実効値／ピーク。単位はADCカウント |
| `attackPeakCounts` | 直近の立ち上がりから最大6ブロックのピーク。描画の合間のピークも保持 |
| `needleDb / fast` | 現在の絶対／相対表示単位での針用の値と速度。平均二乗値を指数平滑。時定数の初期値はSLOW 300 ms／FAST 60 msで、スケッチの共通設定で変更できる。未校正・平滑化後の値がゲート未満ならNaN |
| `absoluteDbV / relativeDb` | 平滑化前の電圧レベル／手動基準との差。未校正・無音はNaN |
| `idle / attack / clipped` | 無音が続いた（またはVIEW長押しで待機を指定した）、前回描画から新しい立ち上がりがあった、ADCが端に近づいた |
| `entered` | 演奏画面では画面切替・再描画・待機からの復帰。待機作品では入場時または登録関数を変更したときにtrue |
| `timeMs / dropped` | 起動からのms、処理しきれなかったADCブロックの累計 |

**再現の目安。** UNOでコンパイル、無音と演奏の切り替わり、MODE／SPEED、校正前、過入力で表示を確認する。自分のスケッチを配布するときは、使用した画像・音の作者と利用条件を添える。配線図を改変した場合は変更点と元の帰属を記す。[クレジットと適用範囲](../THIRD_PARTY_NOTICES.md)
